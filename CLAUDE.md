# Deadlockalytics

Personal second-screen companion site for Valve's **Deadlock**, for a new player. Main target is a portrait 1080×1920 monitor; it must also work at 1920×1080 landscape. Dark art-deco theme (gold on midnight) with lots of animation.

## Commands
- `npm run dev` starts http://localhost:5173. Check first whether it's already running before starting another.
- `npm run build` runs `tsc --noEmit` and `vite build`. Run it after every change; it's the main check.
- `npm run refresh-data -- "<patch label>"` refreshes `data/*.json` from deadlock-api.com after a patch.
- Screenshots and Playwright are not wanted. The user checks the UI on their own monitors.

## Layout
- `src/App.tsx`: the tab shell. It has 9 tabs, `#hash` routing, keys 1–9, `/` to search, the mini match clock and the footer.
- `src/tabs/*.tsx`: one file per tab. `tabs/index.tsx` exports them, plus stubs for tabs that aren't built yet.
- `src/lib/`:
  - `data.ts`: typed imports of `data/*.json` (heroes, items, map, ranks, meta).
  - `content.ts`: typed imports of `content/*.json`.
  - `api.ts`: live deadlock-api analytics, cached in localStorage for 1h.
  - `trends.ts`: win and pick rates, tiers, deltas, matchups.
  - `timer.ts`: the shared match clock and timeline maths.
  - `motion.ts`: the motion toggle.
- `src/components/`:
  - `common.tsx`: TabHeader, Card, Flag, SourceList, Img, Rich.
  - `Modal.tsx`.
  - `ItemBits.tsx`.
- CSS is plain global CSS, split into `styles.css` (tokens and shell), `styles-catalog.css`, `styles-heroes.css` and `styles-guide.css`.
- `data/` is generated by the refresh script, so never hand-edit it. `content/` is hand-written guide text, and each file has `asOfPatch`, `sources` and `flags`.

## Hard rules
- **No League of Legends comparisons**, anywhere. Explain Deadlock on its own terms.
- **No Claude attribution in git.** Never add `Co-Authored-By` lines or "Generated with Claude Code" to commits or PRs. The repo is public on GitHub (tethos/deadlockalytics) and the user doesn't want Claude listed as a contributor.
- **Never invent numbers.** Every timing, stat or value comes from the API or a cited source. Anything unverified gets a `<Flag>` or `flags[]` entry. If live stats fail, show an empty state, never a guess.
- Every tab shows a TabHeader with a DataStamp and its sources, and credits go in the footer.
- Build in small milestones, report after each one, and wait for the user's go-ahead before the next.
